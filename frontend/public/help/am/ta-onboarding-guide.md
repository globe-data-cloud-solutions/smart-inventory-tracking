## ይህን መመሪያ እንዴት መጠቀም እንደሚቻል

| ታዳሚ | ክፍሎች |
|----------|----------|
| **ሁሉም ተጠቃሚዎች** (NM, RM, WM, LM, AU) | ደረጀ 7–8, የ NM ፈጣን ማጣቀሻ, የተለመዱ ጥያቄዎች |
| **🔒 Tenant Administrator (TA) ብቻ** | ደረጀ 1–6, 9, የተጠቃሚ አስተዳደር, የማፅደቅ ህግ ለውጦች |

> **TA-ብቻ ክፍሎች** በዚህ መመሪያ ውስጥ በ🔒 ምልክት ተደርገዋል።

**የሚገመተው የማዋቀር ጊዜ:** ለመጀመሪያ ማዋቀር ደቂቃ 45–90።

### ሚናዎች ከድርጅትዎ ጋር እንዴት እንደሚገናኙ

**ፖዚሽን** (ደረጀ 3) ሲፈጥሩ፣ ከ SMART ቅድመ-ተገለጸ ሚና ኮዶች ውስጥ አንዱን ይመድቡለታል (ሙሉ ዝርዝሩን
ለ[መጀመሪያ ገጽ → የስርዓት ሚናዎች](GETTING_STARTED.md#system-roles-summary) ይመልከቱ):

- **L1 nodes** (ከፍተኛ ደረጀ፣ ለምሳሌ Main Factory) → **NM** ፖዚሽኖችን ይመድቡ
- **L2 nodes** (ለምሳሌ Regional Center) → **RM** ፖዚሽኖችን ይመድቡ
- **L3 nodes** (ለምሳሌ Sub Region) → **RM** ፖዚሽኖችን ይመድቡ
- **L4 nodes** (ለምሳሌ Warehouse Area፣ ክምችት-ያላቸው) → **WM** ፖዚሽኖችን ይመድቡ
- **LM** ፖዚሽኖች በ**ማንኛውም node ደረጀ** ሊፈጠሩ ይችላሉ — LM ከዛ ለትክክለኛው node ብቻ ይወሰናል
- **ተከራይ-ጠቅላላ** (ለ node ያልተገደደ) → **AU** ፖዚሽኖች፣ እና ፖዚሽን ያልተመደበላቸው **LM** መለያዎች

> **ማስታወሻ:** የ TA ሚና የአስተዳዳሪ መለያዎ ብቻ ነው — ለመደበኛ ሰራተኞች TA ፖዚሽኖችን አይፈጥሩም። NM የኦፕሬሽን ሰራተኞችዎ የሚጠቀሙት ከፍተኛ ሚና ነው።

## የጥቅል ደረጀዎች (Packages)

የ SMART የስራ ቦታዎች ከሶስት ጥቅሎች በአንዱ ላይ ናቸው፦ **Starter**, **Growth**, ወይም **Enterprise**።
ጥቅል ሲመዘገቡ ይመርጣሉ፣ ወይም የ SMART አስተዳዳሪዎ ሲያስገቡዎት ይመርጣል። ጥቅልን በኋላ **ለመቀየር**፣
የ SMART አስተዳዳሪዎን ያግኙ — ከመተግበሪያው ውስጥ እራስዎ መቀየር አይችሉም።

እያንዳንዱ ጥቅል ገደቦችዎን እና ምን ባህሪያት እንደተካተቱ ይወስናል። የተለመዱ ነባሪዎች:

> **ከላይ ያሉት አሃዞች ነባሪ ናቸው እና ሊሻሻሉ ይችላሉ።** የመመዝገቢያ ገጹ ሁልጊዜ የአሁኑን የጥቅል ይዘት እና
> ዋጋዎች ያሳያል፣ እና **ቅንብሮች → Tenant Admin → Plan** ለ*የራስዎ* የስራ ቦታ የሚተገበሩትን ትክክለኛ ገደቦችን
> እና ባህሪያትን ያሳያል። ጥቅሎች ከጊዜ ወደ ጊዜ ይሻሻላሉ፤ ማሻሻያ አዲስ ምዝገባዎች እና የጥቅል ለውጦች ላይ ይተገበራል፣
> ያለውን የስራ ቦታ ገደቦች በራሱ አይቀይርም።

**የ TA መለያ ነፃ ነው።** የራስዎ TA መለያ በሰራተኛ-መለያ ገደብ ውስጥ አይቆጠርም። **መጋዘኖች = ክምችት የሚይዙ ቦታዎች;
ለማፅደቅ-ብቻ ቦታዎች ነፃ ናቸው** — የድርጅት node ክምችት ከያዘ ብቻ (`is_stock_holding = true`) ወደ መጋዘን ገደብ ይቆጠራል።

**ዋጋዎች።** እያንዳንዱ ጥቅል ወርሃዊ እና ዓመታዊ ዋጋ አለው። ዋጋዎች ከቫት በፊት ይታያሉ፣ **15% ቫት** እና
ጠቅላላ ድምር ተለያይተው ይታያሉ። የዋጋ ለውጥ **ለቀጣዩ ህዳግ** ይተገበራል፤ አስቀድመው የተቀበሉትን ደረሰኝ በፍፃሜ
አይቀይርም።

**ጥቅል መቀየር።** የጥቅል ለውጦች በ SMART አስተዳዳሪዎ ይከናወናሉ። አዲሱ ገደቦች እና ባህሪያት **ወዲያውኑ**
ይተገበራሉ፣ አዲሱ ዋጋ ከ**ቀጣዩ ደረሰኝ** ይከፈላል።

- **ወርሃዊ ክፍያ:** ለቀሪው የአሁኑ ወር ተጨማሪ ክፍያ አይከፈልም።
- **ዓመታዊ ክፍያ — ማሻሻል:** ያሻሻሉበት ቀሪ ወር ነፃ ነው። በአሁኑ ዓመትዎ ውስጥ ቀሪ **ሙሉ ወራት** ላይ፣
  በአዲሱ እና አሮጌው ዓመታዊ ዋጋዎች መካከል ያለውን **ልዩነት**፣ በወር ተመጣጣኝ፣ ከቫት ጋር ደረሰኝ ይደርሶታል።
  *ለምሳሌ:* Starter 1,000 → Growth 2,000 ከ7 ሙሉ ወራት ቀሪ ጋር:
  (2,000 − 1,000) × 7 ÷ 12 = 583.33 + 87.50 ቫት = **670.83 ብር**።
- **ማቀነስ:** ዝቅተኛ ገደቦች ወዲያውኑ ይተገበራሉ። ለአሁኑ ጊዜ **ተመላሽ ወይም ክሬዲት የለም**፤ ዝቅተኛ ዋጋ
  ከቀጣዩ ደረሰኝ ይተገበራል።

ይህ የማሻሻያ ደረሰኝ በደረሰኝ ዝርዝርዎ ውስጥ **Proration** ተብሎ ይጠቀሳል። መክፈሉ ኮንትራትዎን ወይም የክፍያ
ቀናትዎን አይቀይርም።

**Add-ons።** በጥቅልዎ ውስጥ ያልተካተተ ባህሪ (ለምሳሌ API Access) በ SMART አስተዳዳሪዎ በራሱ ሊጨመር ይችላል።
ወዲያውኑ ይሰራል እና ከቀጣዩ ደረሰኝ ጀምሮ ከጥቅልዎ ጋር ይከፈላል። በ**ዓመታዊ** ክፍያ ላይ በአሁኑ ዓመትዎ ውስጥ ቀሪ
ሙሉ ወራት ላይ በ add-on ዓመታዊ ዋጋ (በወር ተመጣጣኝ፣ ከቫት ጋር) **Proration** ደረሰኝ ይደርሶታል፤ የአሁኑ ወር
ቀሪ ነፃ ነው። Add-on መሰረዝ ወዲያውኑ ያቆመዋል፣ ተመላሽ የለም።

3. ልጅ nodes ይጨምሩ — መጀመሪያ ወላጅ ይምረጡ፣ ከዚያ ልጅ ይጨምሩ
4. ሙሉ የድርጅት ገበታዎ ወደ ስርዓቱ እስኪገባ ይድገሙ

**ምክሮች:**
- ሁሉም ቅርንጫፎች ተመሳሳይ ጥልቀት መያዝ የለባቸውም (የተለያየ-ጥልቀት መዋቅሮች ይደገፋሉ)
- ተመሳሳይ፣ ኦፊሴላዊ ስሞችን ይጠቀሙ — በሪፖርቶች እና የኦዲት ምዝግቦች ውስጥ ይታያሉ
- ድርጅትዎ እያደገ ሲሄድ በኋላ ተጨማሪ nodes መጨመር ይችላሉ

## Organisation Manager (NM) — ፈጣን ማጣቀሻ

*ይህ ክፍል ለ Organisation Managers እና ኦፕሬሽናል ሰራተኞች ነው።*

### ግዴታዎችዎ
- ምርቶችን መፍጠር እና ማስተዳደር
- ዝውውሮችን ማገምገም እና ማፅደቅ
- Send Stock (PUSH) ዝውውሮችን መጀመር
- የክምችት ደረጀዎችን መከታተል
- የማፅደቅ ፖሊሲዎችን ማየት

### ዝውውሮችን ማፅደቅ

1. ወደ Transfers ገጽ ይሂዱ
2. "Pending Review" ወይም "Pending Approval" ሁኔታ ያላቸውን ዝውውሮች ያግኙ
3. ዝርዝሮችን ያገምግሙ (ምርት፣ መጠን፣ ምንጭ፣ መድረሻ)
4. **Review** ከዚያ **Approve** ይጫኑ — ወይም ተገቢ ካልሆነ **Reject**

### ክምችት ማውጣት እና ማሰራጨት

1. በ Transfers ገጽ ላይ Approved ዝውውር ያግኙ
2. ክምችት ለመንቀሳቀስ ዝግጁ መሆኑን ለማረጋገጥ **Issue** ይጫኑ
3. ከምንጩ መውጣቱን ለማረጋገጥ **Dispatch** ይጫኑ
4. መድረሻ WM ከዚያ ይቀበለዋል

> **በስም ተግባር:** የምንጩ መጋዘን ለሌላ ተቋም የሚገባ ዝውውርን Issue/Dispatch ካደረጉ፣ ስርዓቱ "Acting on behalf of: [Warehouse Name]" ያሳያል እና ይህን በኦዲት ምዝግብ ይመዘግባል።

### የማፅደቅ ፖሊሲዎችን ማየት

ለማየት በናቪጌሽን ውስጥ **Approval Policies** ይሂዱ:
- የእርስዎን በእያንዳንዱ የግብይት ዓይነት የራስ-ማፅደቅ ገደቦች
- የትኞቹ ምርቶች 🔒 ልዩ ማፅደቅ ፍላጎት እንዳላቸው
- ሙሉ የፖሊሲ ማትሪክስ (TA/SA ሁሉንም ደረጀዎች ያያሉ)

## ተከታይ አስተዳደር

### 🔒 አዲስ ተጠቃሚ መጨመር (TA ብቻ)
1. Org Setup → Personnel → "+ Add Person"
2. ስም፣ ኢሜል፣ ሚና ያስገቡ፣ ወደ ፖዚሽን ይመድቡ፣ የሚስጥር ቁጥር ያስቀምጡ
3. የማረጋገጫ ዝርዝሮችን በጥንቃቄ ያጋሩ

### 🔒 ተጠቃሚን ማቦዘን (TA ብቻ)
1. Personnel ዝርዝር → ተጠቃሚውን ያግኙ → Active ን ያጥፉ
2. መለያው ወዲያውኑ ይቆለፋል

> **⚠️ ማስታወሻ:** የታቦዘ ተጠቃሚ በመጠባበቅ ላይ ያሉ ማፅደቆች ካለው፣ የ SMART አስተዳዳሪዎን ያግኙ። ራስ-ሰር ዳግም-መምራት በቀጣይ ዝማኔ ይመጣል።

### 🔒 ተጠቃሚን ዳግም ማንቃት (TA ብቻ)
1. Personnel ዝርዝር → ያልነቀውን ተጠቃሚ ያግኙ → Active ን መልሰው ያብሩ
2. የቀደመው ዋና ፖዚሽናቸው ራስ-ሰር ይመለሳል — በራስዎ ዳግም መመደብ አያስፈልግም
3. ተጨማሪ ፖዚሽኖች (acting ወይም delegate ምደባዎች) ይዘው ከነበሩ፣ ዋናው ፖዚሽን ብቻ ራስ-ሰር ይመለሳል፤
   ገና ካስፈለገ acting ወይም delegate ፖዚሽኖችን በራስዎ ዳግም ይመድቡ

### 🔒 የማፅደቅ ህጎችን ማስተካከል (TA ብቻ)
1. Org Setup → Approval Rules → ህጉን ያግኙ እና ያስተካክሉ
2. መጠኖችን፣ ደረጀዎችን፣ ወይም የፈቃጅ ፖዚሽኖችን ያዘምኑ
3. Save ያድርጉ — ለውጦች ወዲያውኑ ይተገባሉ

- **የማስተካከያ ማፅደቅ ፖዚሽን አፈፃፀም:** የማስተካከያ ማፅደቅ ህጎች የተመረጠ ፈቃጅ ፖዚሽን ይገልጻሉ፣ ግን

## የተለመዱ ጥያቄዎች

**ጥ: ጥቅልዬን እንዴት ላሻ ወይም ልቀይር?**

አዲስ ገደቦች እና ባህሪያት ለውጡ እንደተደረገ ይተገባሉ። በዓመታዊ ክፍያ ላይ ማሻሻል በዓመትዎ ቀሪ ወራት ላይ
የተመጣጠነ **Proration** ደረሰኝ ያስገኛል (ይመልከቱ [የጥቅል ደረጀዎች](#plan-tiers))፤ ማቀነስ ተመላሽ የለውም።

**ጥ: "Proration" ደረሰኝ ምንድን ነው?**
በዓመታዊ የክፍያ ዓመት መካከል ለተደረገ ማሻሻል ወይም add-on የአንድ-ጊዜ ደረሰኝ። በዚያ ዓመት ውስጥ ቀሪ
ሙሉ ወራትን ብቻ ይሸፍናል፤ ለውጡ የተደረገበት ወር ነፃ ነው።

**ጥ: ተመዝግቤ ነገር ግን የማረጋገጫ ኢሜል አልደረሰኝም።**
በመግቢያ ገጹ ወይም በማረጋገጫ ገጹ ላይ **Resend link** ይጠቀሙ። አገናኞች ከ48 ሰዓት በኋላ ያለፉ ናቸው።
ገና ካልደረሰ፣ የስፓም አቃፊዎን ይመልከቱ ወይም SMART ድጋፍን ያግኙ።

**ጥ: "የመለያ ባለቤት" ማን ነው?**
የስራ ቦታውን የመዘገበ ሰው (ወይም በ SMART የተፈጠረ የመጀመሪያ TA)። ለምዝገባ እና ለደረሰኞች ዋናው
ተገኛኝ ነው።

**ጥ: ተጠቃሚዎችን ከጨመርኩ በኋላ የድርጅት መዋቅርን መቀየር እችላለሁ?**
አዎ — አዲስ nodes እና ፖዚሽኖች መጨመር ይችላሉ። ያለኑ ተጠቃሚዎች ምደባቸውን ይጠብቃሉ። node ለማስወገድ፣
መጀመሪያ ተጠቃሚዎቹን ዳግም ይመድቡ።

**ጥ: የድርጅት ደረጀዎችን በኋላ መቀየር እችላለሁ?**
ከአሁኑ የግርጌ ደረጀ በታች በማንኛውም ጊዜ ደረጀ መጨመር ይችላሉ፣ እና የግርጌ ደረጀውን ገና የድርጅት
nodes ከሌለው ማስወገድ ይችላሉ — የ Organisation Levels ትር የመጀመሪያ ደረጀዎችዎን ካስቀመጡ በኋላ
ሁለቱንም ምርጫዎች ያሳያል። በስታክ መሃል ደረጀ ማስገባት ወይም ማስወገድ ራስን-አገልግሎት አይደለም፤ ያስፈለገ
ከሆነ SMART ድጋፍን ያግኙ።

ይህ የተመደበው ፈቃጅ ፖዚሽን ዝውውሩ ከገባ በኋላ ክፍት ሲሆን (ተጠቃሚ ታቦዘ ወይም ዳግም ተመደበ) ሊከሰት

3. በቀጥታ ያፀድቁ ወይም ይከልክሉ (የኦዲት ምዝግብ TA እርምጃውን ይመዘግባል)
4. ከዚያ node አዲስ ዝውውሮች ከመፍጠርዎ በፊት፣ የወደፊት ዝውውሮች በትክክል እንዲመሩ ወደ ፈቃጅ ፖዚሽኑ
   ተጠቃሚ ይመድቡ

በሰራተኛው ትክክለኛ ኦፕሬሽናል ወሰን መሰረት ይምረጡ።

**ጥ: ለሁለተኛ ሰው ፈቃጅ ፖዚሽን ስመድብ ምን ይከሰታል?**

ማስተካከያ ለማፅደቅ ወደ ፖዚሽኑ ሲመራ፣ ስርዓቱ አንድ ያዥ ይመርጣል — በተለምዶ በቅርብ የተመደበው። ይህ
ማለት ለፈቃጅ ፖዚሽን ሁለተኛ ሰው መጨመር የማፅደቅ ተግባራት ከመጀመሪያው ይልቅ ወደ አዲሱ ያዥ ሊመሩ
ይችላሉ። የማፅደቅ አመራር ወደ ያልተፈለገ ሰው የሚሄድ ከመሰለ፣ ያንን ፖዚሽን ምን ያህል ንቁ ተጠቃሚዎች
እንደያዙ ይመልከቱ (Settings → Positions → ያዦችን ይመልከቱ)። ሁለቱም በእውነት ተደምረው-ፈቃጆች
ካልሆኑ በስተቀር፣ የታሰበው ፈቃጅ ብቻ በማንኛውም ጊዜ እንዲይዝ ምደባዎችን ያስወግዱ ወይም ያስተካክሉ።

**ጥ: በመጠባበቅ ላይ ያሉ ዝውውሮች ላይ ፈቃጅ የሆነ ተጠቃሚ ካቦዝኩ ምን ይከሰታል?**
ተጠቃሚ ሲቦዘን፣ የፖዚሽን ምደባቸው ራስ-ሰር ይወገዳል። ስርዓቱ ገና ራስ-ሰር አያስጠነቅቅዎትም — ወደ
ያ ተጠቃሚ የተመሩ በመጠባበቅ ላይ ያሉ ዝውውሮች አሁንም ያንን ተጠቃሚ እንደ ፈቃጅ ያሳያሉ፣ ስለዚህ
በ"Pending Approval" የተጣራ Transfers ራስዎ ማየት ያስፈልግዎታል። እንደ TA ራስዎ ያልፈጠሩትን
ማንኛውንም ዝውውር ማፅደቅ ወይም መከልክል ይችላሉ። Adjustments: መደበኛ ማስተካከያዎች እንደተለመደው
በእርስዎ ሊፀድቁ ይችላሉ። የምርት ማፅደቅ ዝቅተኛ ገደብ የተተገበረበት ማስተካከያ ለተወሰነ ሰው ተቆልፏል፤
ያ ሰው ከቦዘነ በማንም ሊፀድቅ አይችልም — ይከልክሉት፣ እና ፈጣሪው ወደ ንቁ ፈቃጅ እንዲመራ ዳግም
እንዲያቀርብ ይጠይቁ። ፖዚሽኑን ዳግም መመደብ ገና-የቀረበን ማስተካከያ አያነቃቅም። ፈቃጅን ከማቦዘንዎ
በፊት፣ አመራር ያልተቋረጠ እንዲቀጥል ለፖዚሽናቸው ሌላ ተጠቃሚ ይመድቡ።

**ጥ: የማስተካከያ ማፅደቅ ህጎች ማን ማፅደቅ እንዳለበት ሊገልጹ ይችላሉ?**
የማስተካከያ ማፅደቅ ህጎች የመጠን ገደቦችን እና የአመራር ባህሪን ይገልጻሉ፣ ነገር ግን ስርዓቱ በመጨረሻው
ደረጀ የትኛው የተወሰነ ፖዚሽን ማፅደቅ እንዳለበት አያስፈጽምም — የማስተካከያ ማፅደቅ ፈቃድ ያለው ማንኛውም
ተጠቃሚ በመጠባበቅ ላይ ያለ ማስተካከያ ማፅደቅ ይችላል። ማን ማስተካከያዎችን እንደሚያፀድቅ ላይ ጥብቅ
ቁጥጥር ካስፈለገዎት፣ ይህን በቴክኒክ አፈፃፀም ላይ ከመተማመን ይልቅ ለአስተዳዳሪዎችዎ የሂደት ፍላጎት
አድርገው ያሳውቁ።

**ጥ: Logistics Manager (LM) በስርዓቱ ውስጥ በትክክል ምን ማድረግ ይችላል?**
LM ሎጂስቲክስ እና dispatch-ላይ-ያተኮረ ሚና ነው — የክምችት ኦፕሬሽን ሚና አይደለም።
LM የሚከተለውን ማድረግ ይችላል:
- በተመደበው node እና ከዛ በታች ባሉት nodes ሁሉ ላይ ክምችት ማየት
- ዝውውሮችን ማየት እና መዘርዘር
- ጭነቶችን መቀበል እና ማሰራጨት
- ማስተካከያዎችን እና የምርት መረጃን ማየት

LM የሚከተለውን ማድረግ አይችልም:
- ዝውውሮችን መፍጠር ወይም ማስገባት
- ማስተካከያዎችን መፍጠር ወይም ማስገባት
- ዝውውሮችን ወይም ማስተካከያዎችን ማፅደቅ

ሰፊ ኦፕሬሽናል መድረሻ (ማፅደቆች፣ ዝውውሮች መፍጠር) ያለው ሰው ካስፈለገዎት፣ በምትኩ Warehouse
Manager (WM) ወይም Regional Manager (RM) ሚና ይመድቡ። ማስታወሻ: node ምደባ ሳይኖር
ከተፈጠረ (ተከራይ-ጠቅላላ LM)፣ LM በመላው ድርጅት ላይ ክምችት ማየት ይችላል ነገር ግን አሁንም
ከላይ ያሉትን ተመሳሳይ ተግባር ገደቦች አለው።

**ጥ: ሁሉም ተጠቃሚዎች PUSH (Send Stock) ዝውውሮችን መጀመር ይችላሉ?**
አይ። PUSH ዝውውሮች በድርጅትዎ ተዋረድ Level 1 (Factory/Main) እና Level 2 (Regional) ላይ
ባሉ ተጠቃሚዎች ብቻ ሊጀመሩ ይችላሉ — በተለምዶ NM እና RM ሚናዎች። ይህ ክምችት በስርጭት እንዴት
እንደሚፈስ ያንፃባርቃል: ፋብሪካዎች እና ክልላዊ ማዕከሎች ክምችትን ወደ ታች ወደ መጋዘኖች ይገፋሉ፣
በተቃራኒው አይደለም።

Warehouse Managers (WM)፣ Logistics Managers (LM)፣ እና የሳተላይት ሰራተኞች PULL
(Request Stock) ወይም Sister (የጎን ልውውጥ) ዝውውሮችን ብቻ መጀመር ይችላሉ። WM ወደ
መጋዘናቸው ክምችት እንዲላክ ከፈለገ፣ PULL ጥያቄ ማስገባት አለባቸው — NM ወይም RM ዎቻቸው
አይተው ያፀድቁታል።

**ጥ: አዲስ የሳተላይት ዴፖ ጨመርኩ — የማፅደቅ ህጎች ራስ-ሰር ይተገባሉ?**
አይ። አዲስ node (መጋዘን ወይም ሳተላይት) ሲጨምሩ፣ እነሱን እስኪፈጥሩ ድረስ ምንም የዝውውር ወይም
ማስተካከያ ማፅደቅ ህጎች የለውም። ህጎች እስኪጨመሩ ድረስ፣ ከዚያ node ዝውውሮች የስርዓቱን ነባሪ
ባንዶች ያልፋሉ፣ እነዚህም ከታሰበው ፖሊሲዎ ጋር ላይስማሙ ይችላሉ። አዲስ node ከፈጠሩ በኋላ፣ ወደ
Settings → Approval Rules ይሂዱ እና ለዚያ node ተገቢ የዝውውር እና ማስተካከያ ህጎች ይጨምሩ
ሰራተኞች መጠቀም ከመጀመራቸው በፊት።

**ጥ: ሰራተኛ ተሻሽሎ ወይም ወደ ሌላ ሚና ተዛወረ። ምን ማድረግ አለብኝ?**
ተጠቃሚን ወደ አዲስ ፖዚሽን ዳግም ሲመድቡ:
1. በአዲሱ ፖዚሽን PRIMARY ይመድቧቸው (ወሰናቸው በቀጣዩ መግቢያቸው ላይ ወዲያውኑ ይዘመናል)
2. ከዚያ በኋላ ሊይዙት የማይገባ ከሆነ የቀደመውን ፖዚሽን ምደባ ያስወግዱ
   — ለ sole PRIMARY ማስወገድ force-remove ይጠቀሙ (SA token ያስፈልጋል)
3. የቀደመው ፖዚሽን በመጠባበቅ ላይ ያሉ ማፅደቆች ካለው፣ እነዚያ ራስ-ሰር አይገፉም —
   በ"Pending Approval" የተጣራ Transfers/Adjustments ራስዎ ይመልከቱ። በመጠባበቅ ላይ ያሉ
   ዝውውሮች እንደ TA በቀጥታ ማፅደቅ ወይም መከልክል ይችላሉ። በመጠባበቅ ላይ ያሉ ማስተካከያዎች
   እንደተለመደው ሊፀድቁ ይችላሉ፣ የምርት ማፅደቅ ዝቅተኛ ገደብ ማስተካከያውን ለተወሰነ ሰው ካልቆለፈው
   በስተቀር — በዚያ ጉዳይ በማንም ሊፀድቅ አይችልም እና መከልክል አለበት፣ ፈጣሪው ወደ ንቁ ፈቃጅ
   እንዲመራ ዳግም ያቀርባል። ምትኩን መጀመሪያ መመደብ ከዚያ በኋላ ለቀረበው ነገር ሁሉ ይህን ያስቀርላል።

ተጠቃሚው ወደ ከፍተኛ ደረጀ ከተዛወረ (ለምሳሌ WM → RM)፣ የቀደመው WM ወሰናቸው በቀጣዩ መግቢያቸው
ላይ በአዲሱ RM ወሰን ይተካል። ወደ ዝቅተኛ ደረጀ ከተዛወሩ (ለምሳሌ RM → WM)፣ መድረሻቸው በዚያ
መሰረት ይጠበባል። ከፖዚሽን ለውጥ በኋላ ተጠቃሚው ወጥቶ ዳግም እንዲገባ በማድረግ ሁልጊዜ ያረጋግጡ።

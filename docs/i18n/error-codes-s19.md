# Session 19 P6 — backend error code inventory

Every error code the backend can return to a client (literal `"code": "X"` / `'code': 'X'` dict entries, `code="X"` keyword args, and `SomeError("CODE", ...)` positional-first-arg exceptions whose caller turns `str(exc)` into the client-facing `code` field — see `_map_value_error()` in `backend/services/tenant-service/routers/billing.py` and the `DispatchError`/`http_from_engine` path in `inventory-service`), that did not already have an `errors.<CODE>` locale entry as of commit 9eb92a3. Generated by `scripts/check_error_codes.py`. 131 codes, all now added to `locales/en.json` / `am.json` / `or.json` in the following commit.

`detail fields` lists extra keys in the HTTP response `detail` object besides `code`/`message`. `backend message` is the verbatim English string in the source when one exists separately from the code; `none (code-only)` means the backend never attaches a human-readable message (either no `message` key at all, or — for `ValueError`-raised billing/webhook codes — the caller sets `message` to the code string itself, e.g. `billing.py`'s `_map_value_error()`). `needs field (P7)` marks a row where the backend message embeds a value that is not exposed as its own `detail` field today (only reachable via an f-string), so the new locale entry is a generic sentence without that value — a future session should add the field and a placeholder.
